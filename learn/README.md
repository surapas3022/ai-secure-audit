# เรียนตามลำดับ: แอปที่ทำกับ AI ควรตรวจอะไรก่อน

เขียนให้คนที่สร้างแอปด้วย AI และไม่เคยเรียนเรื่องความปลอดภัยมาก่อน อ่านตามลำดับ แก้ทีละข้อ แต่ละเรื่องอยู่คนละไฟล์ ตอนนี้มีไฟล์ของข้อ 1 ข้อที่เหลือจะเพิ่มทีละไฟล์

| ลำดับ | เรื่อง | ทำไมอยู่ตรงนี้ | ตรวจยังไงตอนนี้ |
|---|---|---|---|
| 1 | [key หลุด](01-key-leak.md) | ได้ key ไปก็ใช้ได้ทันที ไม่ต้องมีฝีมือ และอาจเสียเงินจริง | `npx ai-secure-audit` |
| 2 | เห็นหรือแก้ข้อมูลของคนอื่นได้ | บางแอปแค่เปลี่ยนเลขในลิงก์ก็เห็นข้อมูลคนอื่น | ตรวจด้วยคน เครื่องมือตรวจได้ไม่หมด |
| 3 | กฎของฐานข้อมูลเปิดทิ้งไว้ (Supabase, Firebase) | คนนอกอ่านฐานข้อมูลได้โดยไม่ต้องผ่านหน้าเว็บ | ตรวจด้วยคน เครื่องมือยังไม่รองรับ |
| 4 | API ไม่เช็กล็อกอิน หรือเช็กแค่ใน frontend | เรียก API ตรง ๆ ก็ข้ามการเช็กได้ | ตรวจด้วยคน เครื่องมือยังไม่รองรับ |
| 5 | library มีช่องโหว่ | วิธีโจมตีมักเผยแพร่แล้ว แต่ส่วนใหญ่แก้ด้วยการอัปเดต | เครื่องมือยังไม่รองรับ |
| 6 | ตั้งค่า Docker หรือ server ไม่ปลอดภัย | ทำให้ความเสียหายลามหนักขึ้น เกี่ยวเฉพาะคนที่ดูแล server เอง | เครื่องมือยังไม่รองรับ |

ลำดับนี้เป็นการตัดสินของโปรเจกต์นี้สำหรับคนเริ่มต้น โดยดูว่าเสียหายแค่ไหนและโจมตีง่ายแค่ไหน ไม่ใช่อันดับจากมาตรฐาน มาตรฐานที่คนใช้อ้างอิงกันคือ [OWASP Top 10:2025][owasp] ซึ่งจัดอันดับความเสี่ยงของเว็บแอปโดยรวม เรื่องการเข้าถึงข้อมูลที่ไม่มีสิทธิ์ (ข้อ 2 ของเรา) อยู่อันดับ 1 การตั้งค่าไม่ปลอดภัยอยู่อันดับ 2 และปัญหาจาก library กับของที่แอปดึงมาใช้อยู่อันดับ 3

เรียงตามลำดับเพื่อให้รู้ว่าควรเริ่มตรงไหน ไม่ได้แปลว่าข้อหลังไม่สำคัญ

ผล "0 ปัญหา" ไม่ได้แปลว่าแอปปลอดภัย แปลว่าเครื่องมือไม่เจอเรื่องที่มันตรวจได้เท่านั้น

[owasp]: https://top10.owasp.org/2025/
